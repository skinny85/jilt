# Contributing to Jilt
First off, thank you for considering contributing to Jilt!

This document provides a set of guidelines for contributing. 
Following these rules helps us process your contributions quickly 
and keeps the codebase clean and maintainable.

## How Can I Contribute?
### Reporting Bugs
Bugs are tracked using GitHub Issues. 
Before creating a bug report, 
please check the existing issues to ensure it hasn't already been reported.

When creating a bug report, please include as many details as possible:

- A clear and descriptive title
- Steps to reproduce the issue
- Expected vs. actual behavior
- Relevant logs or stack traces

### Requesting Features
Feature requests are welcome! 
To suggest a feature:
- Open a GitHub issue.
- Clearly explain what problem this feature solves and why it would be beneficial to other users.
- Provide examples of how the feature would work or be used.

### Submitting Pull Requests
Check for existing PRs or issues before starting work on a major feature.
For this project, we use the [OneFlow](https://www.endoflineblog.com/oneflow-a-git-branching-model-and-workflow)
Git workflow.

- Fork the repository and create your branch from `develop`.
- Keep your changes focused. Smaller, single-purpose PRs are merged much faster.
- Include tests for any new functionality or bug fixes.
- Ensure all existing tests pass locally before opening the PR.
- Update relevant documentation ([Readme.md](Readme.md), Javadoc).
- Rebase on `develop` before opening the PR.
